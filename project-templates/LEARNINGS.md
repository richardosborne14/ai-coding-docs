# Learnings

Running log of **active gotchas** — traps that will waste time if a fresh session doesn't know about them.
**Check this at the start of every task.**

---

## The Litmus Test

Before adding an entry, ask: **"Would a fresh Cline session hitting this same problem waste 30+ minutes without this entry?"**

- **Yes** → Add it here.
- **No** → Log it in the MCP session memory instead, or don't log it at all.

### What Belongs Here
- ✅ Non-obvious gotchas that will bite you again
- ✅ "If you see X, the fix is Y" solutions to recurring traps
- ✅ Framework/tool quirks specific to this project's stack
- ✅ Environment-specific issues (e.g., "dev server needs X to work")

### What Does NOT Belong Here
- ❌ General observations ("learned that React uses JSX")
- ❌ Task completion notes ("successfully built the login page")
- ❌ Architectural decisions (those go in ARCHITECTURE.md)
- ❌ User preferences (those go in GLOBAL_MEMORY.md)
- ❌ Session summaries (those go in the MCP memory database)
- ❌ Resolved issues that can't recur (graduate these out)

### Graduation Rule
When an entry is no longer an active trap (the root cause was fixed, or the pattern was absorbed into `.clinerules` as a permanent rule), **graduate it** to the MCP memory database and remove it from this file. This file should never exceed ~30 entries.
